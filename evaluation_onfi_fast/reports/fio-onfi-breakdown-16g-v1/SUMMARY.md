# ONFI 开关：fio 性能、阻塞模式与等待分解

全部 90 项通过；其中 78 项启用观察，12 项关闭观察作为开销对照。
源码 `a71c89a91247d2c72a91d0831ad28f834aba215c`；开跑工作区：干净。
正式实验，3 轮独立重建。 A=ONFI关，B=ONFI开；FAST placement 与覆盖识别始终关闭。
16 GiB 物理预留；工作集 2048 MiB，每项固定 2048 MiB 测量 I/O。
其余配置和口径见 [实验协议](../../ONFI_BREAKDOWN.zh-CN.md)。全范围数据模式验证通过，无 GC。

## 关键解释

4 KiB、QD32、50/50 中，ONFI 使吞吐从 796.82 降到 620.16 MiB/s。
NAND read 平均时延增加 89.35 µs，其中本 die 排队项增加 88.21 µs；
NAND program 平均时延增加 167.64 µs，其中直接 ONFI 项增加 142.31 µs。
读请求没有直接的 ONFI program 等待计数，但会等待被推迟的 program，以及排在它后面的其他读。
样本时间线核对到了同 target 的“读阻塞另一 LUN 的 program → 该 program 阻塞本 LUN 的后续读”链。

本配置 85.71% 的 program 触发等待，触发时平均等待 166.04 µs。
其中 76.65% 的累计直接等待发生在阻塞读尚未 sensing 的阶段。
这说明现有资源预订顺序带来的队列会放大 ONFI 成本。该模型对已经预订的未来读保持输出完成屏障，
没有实现重新安排尚未开始的读以给 program 让路；结果应限定为当前 FTL/调度模型，不能当作硬件约束必然造成的固定损失。

主机读写比例也不等于 NAND 操作比例：4 KiB 写会按八个映射页合成一个 32 KiB program，
32 KiB 写则每次即可形成一个 program。
B 组 4 KiB、50/50 的 NAND read/program 数为 786797/98310（约 8.0:1）；
32 KiB 的计数为 98565/98247（约 1.0:1）。
所以两种请求大小的直接冲突率、同 die 排队和性能损失不应只按主机 50/50 比例比较。

4 KiB、QD32、读30% 时，虽然 program 触发比例低于 50/50，但触发次数增加到 106275，
触发时平均等待增至 177.67 µs；写比例增加意味着更多 program。
判断影响要同时看 program 数、触发概率、单次等待和后续队列，不能只看碰撞率。

两种 QD32、50/50 配置的观察开销对照，配对吞吐变化均值范围为 -0.74% 至 +0.70%。
每项标准差在后表给出；这项检查只覆盖指定两种配置。小幅差异保留，不宣称为零开销。

## 真实阻塞链样本

每通道跳过前 2048 条观察命令，再保留 512 条；完整观测计数不受该采样窗口限制。
下面从 r1/B/4k-r50-qd32 的窗口内选择存在完整 read→program→read 关联的样本，按直接 ONFI 等待排序取中位项。
这些事件来自普通均匀随机 fio，没有指定 die 地址或人为安排交替序列。
这是解释机制的实际样本，不是最坏情况，也不代表全运行的中位 I/O。

| 角色 | channel/LUN | 命令序号 | 提交模型时刻 µs | 本 die 排队 µs | ONFI µs | sensing/program 起→止 µs | 数据阶段结束 µs |
|---|---|---:|---:|---:|---:|---|---:|
| blocking_read | 0/0 | 2211 | 0.000 | 518.397 | 0.000 | 518.397→560.157 | 565.021 |
| blocked_program | 0/1 | 2213 | 147.024 | 232.997 | 185.000 | 607.933→792.933 | 607.933 |
| following_read | 0/1 | 2214 | 184.984 | 607.949 | 0.000 | 792.933→822.693 | 827.557 |

时刻相对于该三条记录最早的 NAND 模型请求时间；主机提交时间和 CPU 执行时间不等于此时刻。
第一条读的输出结束界定第二条 program 的 ONFI 屏障；第三条读的 previous_seq 指向该 program，并等待它在同 die 完成。
[完整字段](trace_example.csv)；全部窗口模式计数见 [trace_patterns.csv](trace_patterns.csv)，全量窗口事件在原始归档的 measure.trace 中。
